The Leiden method

We cluster papers with the Leiden algorithm, from Traag, Waltman and van Eck at Leiden University's Centre for Science and Technology Studies (CWTS):

Traag V.A., Waltman L. & van Eck N.J. From Louvain to Leiden: guaranteeing well-connected communities. Scientific Reports 9, 5233 (2019). DOI 10.1038/s41598-019-41695-z. Also at the Leiden University repository.

Community detection finds groups of nodes that cite each other more than they cite the rest of the graph. The older Louvain algorithm, which most bibliometric tools still use, has a known defect: after a few aggregation steps a “community” can be internally disconnected. Two topics that barely cite each other can share a label. Leiden adds a refinement step before each aggregation, so every community stays connected, and iterating it converges to a partition where no subset of a community would rather leave. It is also faster, which is what makes a 17-million-node run feasible.

We do not reimplement Leiden in Python. src/subprocess_leiden.py writes the node and edge lists to disk and shells out to the CWTS jar publicationclassification.jar (nl.cwts.publicationclassification.run.PublicationClassificationCreator) with java -Xmx350g. That is the same lineage CWTS uses to classify the scientific literature.

How the citation network is created

All of this is src/cwts_export.py. The script pulls from AIRAK, weights the edges, and writes four BigQuery tables. Nothing is clustered yet.

1. Seed journals

JOURNAL_IDS is the full Frontiers journal-ID list and overrides TOP_N_JOURNALS. In ego and full modes that list bounds which papers enter the graph. In global mode — the current default — the edge query has no journal filter. The seed only labels which nodes are Frontiers (pub_metadata_raw.is_frontiers).

2. Year window

START_YEAR–END_YEAR is baked into the graph. A paper published outside the window never becomes a node, even as a cited neighbour. The window cannot be widened downstream: a 2023–2026 export cannot support a 2020 drift baseline.

3. Which papers and which edges

ModeWhat enters the graph
egoFrontiers papers in the window plus their immediate citation neighbours, capped at MAX_EXTERNAL_PAPERS.
fullFrontiers journals plus any related journal with at least 50 citation links into or out of that seed, then every paper those journals published in the window.
globalEvery AIRAK citation whose both ends were published in the year window. No journal filter. Current default; on the order of 17 million nodes and 95 million undirected edges.

4. Node IDs

int_id is assigned by sorting AIRAK PublicationId and numbering from zero. It is run-local. The same paper gets a different int_id on the next export, so never join two runs on it.

5. Edge weights

Direct-citation weight is

Older cited papers fade. Same-journal citations are halved so a title's internal habit does not glue its whole output into one community. That is the point of the self-cite discount: without it, Leiden would partly rediscover journals rather than topics.

6. Bibliographic coupling

Optional extra edges between papers that share references, even if they never cite each other. Weight is a cosine over shared refs, kept only when they share at least BC_MIN_SHARED_REFS, capped at 1.0, then summed with the citation weight and capped at 2.0.

In global mode the code force-disables BC, even though the environment default is true. There is no bounded journal set, so the shared-reference query would be unbounded. That is why the V1 run_metadata row has bc_edges_enabled = false.

7. Write-out

Pairs are normalised low-ID first, weights summed, then written in both directions to cit_links_raw. Each undirected edge appears twice. core_pub is currently 1 on every row of pubs_raw, so it cannot separate seed from neighbour papers. Use is_frontiers.

Current defaults

Values below are the defaults in code today, not the V1 snapshot. Changing any of them mints a new run suffix; the old tables stay.

ParameterDefaultWhat changing it does

Leiden clustering — src/subprocess_leiden.py

Lower resolution / higher minimum size gives coarser communities. Tightening micro toward meso merges section-shaped units into journal-shaped ones. Loosening creates more, smaller clusters: noisier names, more candidate “launch sections”.

ParameterDefaultWhat changing it does
largest_component_onlytrueDrops papers off the giant component (about 2.6% on a comparable 17M-node run). Off would assign tiny islands their own clusters, most of them unusable.
iterations1000More iterations, more stable locally-optimal partition. 1000 is already high; cutting it saves runtime and can leave communities less settled.
micro resolution / min size1e-5 / 500Finest level. Used as the drill-down / section-shaped unit. Smaller min size or higher resolution fragments sections further.
meso resolution / min size2e-6 / 5,000Default opportunity community. This is the journal-shaped level the mapper joins on.
macro resolution / min size2e-7 / 100,000Broadest. Used as a sanity check that a scope is not split across fields; not the unit we launch against.
