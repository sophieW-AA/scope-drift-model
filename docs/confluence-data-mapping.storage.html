BigQuery reference for the scope-drift opportunity pipeline. For every table: its columns, the script that writes it, the scripts that read it, and its join keys. How the citation graph is built lives on . How we judge in-scope vs out-of-scope for a journal lives on .

Table names are written as <run> throughout, because the pipeline writes a fresh set of tables on every citation run. The V1 tables section below resolves <run> to the actual names behind the current V1 slate.

The pipeline

Five stages. Graph construction and Leiden defaults are documented on ; this page is the table dictionary. Each stage writes its tables and the next stage reads them — nothing is passed outside BigQuery.

Stages pubs_raw, cit_links_raw, pub_metadata_raw, run_metadata | [raw_citation_network_data] v 2. subprocess_leiden.py -> classification_raw | v 3. taxonomy_naming.py -> cluster_labels_*, cluster_taxonomy_labels_*, cluster_l2_topics_* | [taxonomy_labelling] v 4. build_unified_dashboard.py -> paper_scope | v 5. src/opportunities/ -> everything in [opportunity_mapping]]]>
StageScriptReadsWritesWhat it does
1. Exportcwts_export.pyAIRAKpubs_raw, cit_links_raw, pub_metadata_raw, run_metadataPulls every paper citing or cited by the Frontiers seed set and turns them into a weighted node-and-edge list.
2. Clustersubprocess_leiden.pypubs_raw, cit_links_rawclassification_rawRuns Leiden at three resolutions, giving every paper a micro, meso and macro community.
3. Nametaxonomy_naming.pyclassification_raw, pub_metadata_rawcluster_labels_*, cluster_taxonomy_labels_*, cluster_l2_topics_*Gives each numbered community a human name and a subject-topic profile.
4. Scopebuild_unified_dashboard.pyclassification_raw, pub_metadata_raw, run_metadatapaper_scopeJudges, per journal, which communities are in scope and flags individual papers that drifted out.
5. Opportunitysrc/opportunities/all of the aboveopportunity_mapping.*Sizes markets, works out who owns what, and produces the launch slate.

Inside stage 5

The phases run in this order. Each one reads the previous phase's table, so a partial run needs its predecessors to exist for the same run suffix.

PhaseQuestion it answers
worldWhich research fields are big and growing, independently of Frontiers and of Leiden?
p0What does each Frontiers journal actually publish, by community, and is that mix moving?
p1Does this community belong to this journal, or does another journal already own it?
p2Is the community big enough and persistent enough to matter, and is it driven by Research Topics or by spontaneous submissions?
p3What does the governed JD market reference say about this community?
p4Given all of the above, what should we do — gate, expand, redirect, launch a section, launch a journal, or watch?
p5Which communities in this run are the same as the ones in the previous run?
unitsSized against real journals and sections, what would a launchable unit look like and who owns it today?
finalAcross OpenAlex subfields, which markets justify a new journal, and does the citation network support that scope?

How they link

Two identifiers carry the whole chain. int_id is the run-local paper ID and joins everything in the network layer. community_id is the Leiden community and joins the network layer to the opportunity layer. Both are meaningless outside this run.

cit_links_raw_<run>

Key (int_id1, int_id2). Pairs are normalised low-ID-first, deduplicated with weights summed, then written in both directions; each undirected edge appears twice.

ColumnTypeMeaning

Known issues

IssueDetail
unit_name is emptybq.fetch_l2_topics reads unit_name, l1_roll_name and l1_roll_share, which the current cluster_l2_topics tables do not have. It falls back silently, so unit_name is blank on all 3,021 candidates rows and all 3,405 launch_units rows carry name_source = l2_compound. Re-running taxonomy_naming for this run fixes it.
run_metadata timestamp mismatchrun_metadata_20260827_081311 stores run_timestamp = 20260818_090851 and generated_utc = 2026-08-18 15:43 UTC. The row appears copied from the earlier export. Trust the table suffix for lineage, not the row.
core_pub is constantSet to 1 on every pubs_raw row, so it cannot separate seed from neighbour papers. Use pub_metadata_raw.is_frontiers.
persist_ok is two different columnsvolume.persist_ok means the community appears across enough years. decisions.persist_ok means the same launch call was made in the previous run.
launches filters on callNot call_effective, so unconfirmed proposals are included. Check pending_persist.
paper_scope is partial17,768 rows against 282,689 papers. Unassessed papers default to in scope, so oos_pct understates drift for journals the dashboard does not cover.
Growth is fragileThe run spans 2023–2026, so community growth is a three-step ratio. Check growth_reliable before quoting a CAGR.
Leiden IDs are run-localCommunity IDs carry no meaning across runs. Join through community_matches.
Missing table means no rowsbq.write_table deletes rather than writing an empty table.
Legacy tablesmarket_opportunities_<run> and market_opportunities_meta_<run> have no current producer. taxonomy_labelling.sample_pubs and sample_pub_ids_<level> were last written for run 20260818_090851 and have no code reference.
