Column schema for the stakeholder views in ocean-tech-adv-analytics-c-tfs.clean_views (EU). The views are read-only. They are built by scripts/build_clean_views.py and do not change the source tables. The tables they read are documented on .

Context

Two runs are published together. run_type = 'paper' is citation run 20260827_081311, where a member is a paper. run_type = 'person' is author run 20261023_114612, where a member is an author. The same column names are used for both. A filter works on every view:

sql

Objective / scope

Give stakeholders one place to read both runs without opening the pipeline tables. Detail that exists for only one run type lives in its own view, joined back on member_key.

members

One row per clustered paper or author. Each member sits in one micro, one meso and one macro community. Papers that were exported but not clustered are not in this view.

ColumnTypeMeaning
run_type, run_id, member_typeSTRINGRun keys. member_type is paper or author.

micro_name, meso_name, macro_nameSTRINGCommunity name. Unlabelled communities read Unlabelled <level> community <id>.

Dependencies / risks

  • Community ids are not comparable across run_type or across level. Use community_key.
  • Rebuilding the views replaces the view definitions only. The source tables are not modified.
  • A community with no taxonomy label still appears, with is_labelled = false.
